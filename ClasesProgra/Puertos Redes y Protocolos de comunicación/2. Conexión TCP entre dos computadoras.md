Supongamos:

```
PC A — Linux
IP: 192.168.1.20

PC B — Windows
IP: 192.168.1.30
```
La idea será:

```
                 RED LOCAL
        ┌─────────────────────────┐
        │                         │
        │                         │
   PC A │                         │ PC B
        │                         │
192.168.1.20                  192.168.1.30
        │                         │
        │                         │
   TCP SERVER  ←───────────────  TCP CLIENT
```

# 1. Primero: comprobar que existe conectividad

Desde **PC B**:

```
ping 192.168.1.20
```

Si responde:

```
Reply from 192.168.1.20: bytes=32 time=2ms TTL=64
```

significa que PC B puede llegar a PC A mediante IP.

Pero ojo:

> **Que `ping` funcione no significa que un puerto TCP esté abierto.**

`ping` utiliza **ICMP**, no TCP.


# 2. Crear un servidor TCP

```bash
sudo pacman -S openbsd-netcat
```


En PC A podemos utilizar `nc` (`netcat`).

Primero:

```
nc -lv 5000
```

Dependiendo de la versión de `nc`, puede ser:

```
nc -l -v -p 5000
```

Ahora PC A tiene algo escuchando en:

```
0.0.0.0:5000
```

Podemos comprobarlo con:

```
ss -lnt
```

Podrías ver:

```
State   Local Address:Port
LISTEN  0.0.0.0:5000
```

Aquí aparece un concepto fundamental:

```
LISTEN
```

Significa:

> "Hay un programa esperando conexiones TCP en este puerto."

# 3. Conectarnos desde PC B

Desde Windows podemos utilizar `ncat` si tienes Nmap instalado:

```
ncat 192.168.1.20 5000
```

O si tienes `nc` disponible:

```
nc 192.168.1.20 5000
```

Ahora tenemos:

```
PC B                         PC A

cliente                      servidor
   │                            │
   │──── TCP SYN ─────────────>│
   │<─── TCP SYN/ACK ──────────│
   │──── TCP ACK ─────────────>│
   │                            │
   │════ conexión TCP ═════════│
```

La conexión está establecida.

# 4. Mandar datos

En PC B escribe:

```
Hola PC A
```

Y presiona Enter.

En PC A deberías recibir:

```
Hola PC A
```

Ahora escribe desde PC A:

```
Hola PC B
```

Y podrás verlo en PC B.

Acabamos de construir un pequeño **chat TCP** usando solamente:

```
IP + TCP + puerto + cliente + servidor
```

# 5. Ver la conexión con `ss`

Mientras la conexión está activa, en PC A:

```
ss -nt
```

Podrías encontrar:

```
State       Local Address       Peer Address
ESTAB       192.168.1.20:5000   192.168.1.30:52341
```

Ahora aparece:

```
ESTAB
```

que significa:

> **ESTABLISHED** → existe una conexión TCP establecida.

Observa algo interesante:

```
192.168.1.20:5000
       ↑      ↑
       IP    puerto del servidor
```

y:

```
192.168.1.30:52341
       ↑      ↑
       IP    puerto del cliente
```

El cliente también tiene un puerto.

Normalmente es un **puerto efímero**, elegido automáticamente por el sistema operativo.

# 6. Ahora viene la parte interesante: `tcpdump`

```
sudo pacman -S tcpdump
```

En PC A puedes ejecutar:

```
sudo tcpdump -i any tcp port 5000
```

Ahora vuelve a conectar desde PC B.
```
nc -lv 5000
```

Podrás observar paquetes similares a:

```
192.168.1.30.52341 > 192.168.1.20.5000: Flags [S]
192.168.1.20.5000 > 192.168.1.30.52341: Flags [S.]
192.168.1.30.52341 > 192.168.1.20.5000: Flags [.]
```

Esto es el famoso **three-way handshake de TCP**:

```
CLIENTE                         SERVIDOR

   SYN ──────────────────────────>

       <──────────────── SYN + ACK

   ACK ──────────────────────────>

          CONEXIÓN ESTABLECIDA
```

Y ahí empiezas a ver que TCP no es algo abstracto.

Son realmente **paquetes viajando por la red**.
